# 40 — 姿态会话 + 帧上行 + 周期切分

**What to build:** 用户架好手机进入姿态纠错后，前端持续把骨架关键点推上来，后端开一个短生命周期会话并按动作周期（一次完整动作，常态 2–4 秒）把关键点序列切段：不成周期就继续等、不产生任何评估；成周期就交给后续识别与评估。会话可结束并拿到本次已完成的周期数。本票只做会话与切段，评估与高亮在下一票。

**Blocked by:** 06 迁移基线对齐与一致性测试；07 今日接口区分「无计划 / 休息日」

**Status:** ready-for-agent

- [ ] AC1：创建会话返回 200，含会话标识、有效期与建议上传间隔；帧批只接受关键点数据（坐标 + 可见度），不接受图片或视频；未登录 401。
- [ ] AC2：推送不足一个完整动作周期的帧时，会话保持等待态（响应无评分、无反馈），且不发起任何模型调用（替身计数为 0）。
- [ ] AC3：推送一个完整周期（合成序列，时长落在 1.5–6 秒）后返回该周期的标识与起止信息，周期时长落在声明边界内；超出边界的信号不构成新周期。
- [ ] AC4：单批帧数与单会话总帧数上限在服务端强制，超限返回 4xx 且错误可读，不静默截断。
- [ ] AC5：关键点质量差的周期（低可见度占比高、人体出框、多人入镜）标记为不可评估，返回机位提示且不给评分、不消耗模型调用。
- [ ] AC6：结束会话返回 200 与本次已完成的周期数；结束后再写入帧或取结果返回 4xx 稳定错误码（与「服务器错误」可区分）；他人会话 403。
