# 20 — 计划解释字段落库与读取

**What to build:** 计划现在能告诉用户"练什么"，但生成依据和调整依据都留不下来。打卡后 AdjustGraph 确实算出了加量/减量/保持的结论和一句人话理由，调用链却只把改完的动作列表写回计划，理由与方向在出口就丢掉了；生成计划时后端其实已经存了当次的体型分析快照，但它从不出现在计划读取的响应里，前端也拿不到；难度系数生成后永远是初始值，没有任何地方记录它为什么变过。

这张票把这两类信息补齐并对外可读：读计划时能拿到"生成依据"（体型分类、体脂区间、弱势肌群、优势部位、分析结论摘要、该次分析的时间、生成时的档案目标）和"最近一次调整说明"（**由 08 的调整结论记录投影而来**：方向、触发指标为完成率、完成率数值、发生时间、一句理由；计划侧只保存该结论的引用，不复制一份文本——Lead 裁决）。新增字段全部可空，旧计划读取仍然成功、解释为空，不回填历史。

这是改表，因此必须遵守全组统一的迁移与数据模型落地约定（ORM 为唯一事实源、迁移与模型手写对齐、随本交付追加 revision、可回滚），不得自立一套。

**Blocked by:** 08 调整结论落盘最小契约

**Status:** ready-for-agent

- [ ] AC1：完成一次打卡并触发 AdjustGraph 后，读取当前计划能拿到最近一次调整说明：方向落在加量/减量/保持三者之一、触发指标为完成率、完成率数值与本次打卡的完成组数/计划组数一致、发生时间可读、理由非空（路由层用调整图替身断言）。
- [ ] AC2：生成计划后读取当前计划能拿到生成依据：体型分类、体脂区间、弱势肌群、优势部位、分析结论摘要、该次分析的时间、生成时的档案目标；其中体型分类取值可落在 ectomorph / mesomorph / endomorph 之一。
- [ ] AC3：旧计划（解释与快照均为空的存量数据）读取时仍返回成功响应，解释字段为 null，不抛错；只填了部分子字段的计划也能读取成功，缺失子字段不导致失败（两条路由层用例）。
- [ ] AC4：迁移遵循全组统一约定：ORM 为唯一事实源、迁移文件与模型手写对齐、随本交付追加一个 revision、downgrade 可回滚；空库上「按 ORM 建表」与「按迁移升级」得到一致的表与列集合（一致性测试全绿）。
- [ ] AC5：计划读取响应仍保留难度系数等既有字段（兼容现有调用方），且新增解释结构不改变既有字段的类型与含意（一条回归断言）。
