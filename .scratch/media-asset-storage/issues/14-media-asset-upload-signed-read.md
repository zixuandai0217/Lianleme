# 14 — 媒体资产实体 + 原图上传 + 签名读图

**What to build:** 用户上传的全身照第一次真正存进对象存储，数据库里只剩引用与元数据，不再有 base64。用户需要原图时拿到的是一个短时有效的签名链接——别人拿到这个链接，几分钟后就打不开了；也就是说，身体照片不再靠「没人知道地址」来保护。历史与详情接口开始返回原图与缩略图的签名 URL 字段（缩略图本票阶段为空，由 15 填入），旧的内联缩略图字段进入弃用窗口。分析任务的创建同时从「传图片内容」改为「传资产标识」，兼容期仍接受内联图片，但服务端会先把它落成资产，任务表与历史表里永远不会再出现图片字串。

**Blocked by:** 06 迁移基线对齐与一致性测试、09 分析任务实体与创建接口

**Status:** ready-for-agent

- [ ] 上传接口接受图片并返回资产标识与元数据（内容类型、字节数、宽高）；数据库该资产记录不含图片字串、不含任何 URL。
- [ ] 对象存储中出现对应对象，key 含环境与用户前缀和年月、不含用户原始文件名；重复上传同一校验摘要返回同一资产标识且对象数量不增加。
- [ ] 签名读图接口：本人换取成功并得到短时有效 URL；他人、未登录、已删除资产一律返回 403 或 404（语义固定、不因存在性而不同）；同一 URL 过期后不可再用。
- [ ] 分析任务创建接受资产标识并成功建任务，任务记录中不含图片内容；兼容期内联图片请求同样成功，且服务端先落成资产。
- [ ] 历史与详情接口返回原图签名 URL 与缩略图字段（本票阶段缩略图为空或降级标记，15 填入真实值）；旧的内联缩略图字段返回空值且不报错。
- [ ] 对象存储不可用时上传返回 5xx 服务暂不可用语义，且数据库中没有新增任何 base64 记录。
