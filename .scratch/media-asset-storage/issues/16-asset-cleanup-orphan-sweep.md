# 16 — 资产清理与孤儿巡检

**What to build:** 删除是真的删除。用户删掉一条分析记录，对应的原图与缩略图最终从对象存储消失，之前拿到的签名链接随之失效；注销或合规删除请求能按用户一次性清空他的全部媒体资产，并留下删了多少个对象的计数。反过来，没人引用的孤儿对象（上传成功但记录没写成功、或者清理中断留下的）会被巡检发现后清掉，存储成本不再只涨不降。巡检也看另一个方向：记录还在但对象丢了，资产会被标记降级并留下事件，而不是等用户点开历史时才发现一片破图。

**Blocked by:** 15 请求期校验 + 缩略图异步生成

**Status:** ready-for-agent

- [ ] 删除一条分析记录后，对应资产进入待清理并最终从对象存储删除；此后再用之前的签名 URL 或重新换取 URL 都不可访问（404）。
- [ ] 用户级清理按用户前缀批量删除其全部资产，返回或记录删除对象计数；重复执行不报错，且不会删除其他用户的任何对象。
- [ ] 孤儿巡检：对象存在但无任何资产引用且超过宽限期则被删除；未超过宽限期的孤儿对象保持不动（用可控时间推进断言）。
- [ ] 反向巡检：资产记录存在但对象缺失时，资产状态置为「已降级」并产生一条事件；此时签名读图返回降级或不可用语义，不是 5xx。
- [ ] 清理分批执行且带计数日志：单批数量受配置约束，全量清理不产生长事务（以批次数与计数事件断言）。
