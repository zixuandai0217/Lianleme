# 30 — 计划页 / 分析页空态联动

**What to build:** 首页引导定好"当前缺哪一步"之后，计划页的空态与分析页的阶段闭环要跟它说同一件事。今天这三处各写一套判定：计划页空态把"生成一周训练"写死成当前步骤（无论用户是否已有计划），分析页另有一套四阶段语言，首页又是第三套，用户在不同页面看到互相矛盾的"下一步"。

这张票把两处页面改成共享判定的投影：计划页空态取"步骤清单"形态，分析页继续用它的四阶段闭环形态，但"当前缺哪一步"的值只能来自同一个判定。同时修掉两个首用体验问题：计划页把"还没有计划"这条正常首用状态渲染成红色错误条；空态里的档案入口指向个人资料页，而健身档案实际在身体数据页，用户点过去看不到表单。

**Blocked by:** 29 下一步判定纯函数 + 首页引导卡

**Status:** ready-for-agent

- [ ] AC1：同一份状态快照下，首页、计划页空态、分析页三处显示的当前步骤一致；用同一份用例表（缺 Key / 缺档案 / 缺分析 / 缺计划 / 缺打卡 / 已完成）驱动三个页面断言，任何一页出现不同结论即失败（jsdom 渲染 + mock 认证与 API）。
- [ ] AC2：计划页空态的当前步骤由共享判定决定，不再把"生成一周训练"写死为当前步；已有计划但未打卡的用户在计划页看到的当前步与首页一致（一条断言）。
- [ ] AC3：计划页在"还没有计划"时渲染中性空态，不出现红色错误告警条；计划查询失败（非资源不存在）时也降级为中性提示，不提示用户去生成计划（两种情形各一条断言）。
- [ ] AC4：计划页空态的档案入口指向实际承载档案表单的页面（身体数据）；未配 Key 的用户该入口按共享判定改为配置 Key，且入口只有一个主行动（一条断言）。
- [ ] AC5：分析页四阶段闭环的阶段状态由共享判定得出：已满足的阶段为 completed、当前步 active、其余 pending；分析已完成但无计划时主行动为"生成专属训练计划"，有计划时切换为"查看训练计划"（两态各一条断言）。
