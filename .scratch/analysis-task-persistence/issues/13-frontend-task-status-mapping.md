# 13 — 前端任务状态映射与终止态

**What to build:** 分析页的等待体验收口。五种任务状态各有一句人话和一个下一步动作，用户不用猜现在是排队、在算、算完了还是不会再算了。最关键的是终止态：一旦任务过期或重试耗尽，页面立刻停止等待并给出「重新发起」，而不是像现在这样一直转到 120 秒上限才弹一句「分析超时、请稍后重试」——那时候用户已经白等了两分钟，而且不知道到底发生了什么。轮询节奏改为听服务端的（服务端知道自己的过期时间），次数上限只作为服务端异常时的最后保险。

**Blocked by:** 10 任务轮询改读数据库

**Status:** ready-for-agent

- [ ] 一个纯函数把任务状态映射为「展示文案 + 主/次动作 + 是否终止等待」：`pending`、`processing`、`completed`、`failed`、`expired` 五态各有确定输出，五态均被单元测试覆盖且全绿。
- [ ] `expired` 与「重试耗尽」被判定为终止态：页面立即停止轮询、显示可重新发起的入口，且不再发出后续轮询请求（页面级测试断言请求次数不增长）。
- [ ] 轮询间隔优先采用服务端返回的建议值；服务端未提供时回退到既有默认间隔，轮询次数上限仍然生效。
- [ ] 失败态展示服务端 `error.message` 的安全文案，并按 `retryable` 决定是否提供自动重试入口；页面任何位置都不出现原始异常文本、堆栈或供应商原文。
- [ ] 分析完成后的既有链路（结果展示 → 生成训练计划 → 进入训练）回归通过，既有前端测试全绿。
