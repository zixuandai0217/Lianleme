# 17 — 陪练协议帧 + 服务端清洗 + 前端协议层

**What to build:** 把陪练输出从「谁的文本都能过」的自定义流变成一条有类型的事件流。服务端每帧发一个 JSON 对象（类型判别在帧内，帧之间空行分隔），正文只来自正文增量帧；一轮以开场帧开始、以收尾帧结束，收尾帧只有一个。模型的原始输出在离开服务端之前统一清洗：JSON 外壳、代码围栏、结构化残留一律不进入用户可见文本，清洗后的文本才入库，因此历史回放与实时看到的是同一份内容。

前端相应地把解析从页面里抽出来，变成一个与渲染无关的协议层：帧解码器负责把字节流拼成事件（跨块拼帧、一帧被切成两段、多帧同块、心跳注释行都要能吃下），轮次归约器负责把事件序列收敛成气泡正文、教练状态、快捷动作与终结原因。页面只消费归约结果，不再自己按行切 `data:` 拼字符串。事件形状以 coach-stream-protocol spec 第 1 节为唯一来源，不在本票内重新定义。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] AC1：陪练流式接口的响应中每一帧都是可解析的单行 JSON，且帧序列以开场帧（含协议版本与轮次标识）开头、以唯一的收尾帧结尾，用户可见正文只来自正文增量帧。
- [ ] AC2：当模型返回 JSON 外壳或带代码围栏的内容时，用户可见正文不含 `{"reply"` 这类结构标记与反引号围栏，正文等于其中的回复文本；该轮的收尾原因为正常完成。
- [ ] AC3：当模型正文包含换行或多行代码块时，全部帧仍是合法 JSON；前端解码器在「帧被任意位置切断」「多帧落在同一块」「夹带心跳注释行」三种喂入方式下产生同一事件序列。
- [ ] AC4：当整轮输出清洗后无可读内容时，出现一句兜底文案、收尾原因为正常完成，界面不出现永久空白气泡。
- [ ] AC5：页面渲染的正文来自协议层归约结果（页面内不再有对原始响应按行切分的拼接逻辑）；遇到未知事件类型或字段缺失时界面不崩、状态仍正确。
- [ ] AC6：非当前轮次的迟到帧（轮次标识不匹配）被丢弃，不会串进当前气泡；同一轮内重复或乱序的收尾帧不改变最终状态。
