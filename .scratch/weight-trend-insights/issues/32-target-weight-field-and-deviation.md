# 32 — 目标体重字段同步 + 偏离判定

**What to build:** 档案里有健身目标（减脂/增肌/塑形/提升体能），但体重模块从来没用过它：方向判断默认"下降就是绿、上升就是红"，对增肌用户这是错误的价值判断；档案里也没有任何数值目标体重，所以"是否偏离目标"在数据上根本回答不了。

这张票补上目标判断的最后一环。先在身体档案增加可选的数值目标体重，并保证保存后能读回；再让 31 的解读区根据目标给出"朝目标前进 / 偏离 / 基本持平 / 数据不足"的结论：有数值目标就按"当前体重与目标的差距 + 最近 30 天方向"判断，没有就退化为方向判断（减脂看下降、增肌看上升、塑形与提升体能看维持），并显式标注这是按目标方向推断。颜色语义随之改为"朝目标为正色、背离为警示色、无目标为中性"。

实现时必须注意现有档案接口是"整体替换 + 丢弃空值"：页面保存档案要一次性提交全部档案字段，否则未提交的字段会被清空；档案模型是严格校验的，只改前端不生效，前后端字段要同时加。目标体重存在既有档案里，不涉及数据库迁移。

**Blocked by:** 31 体重趋势统计与解读区

**Status:** ready-for-agent

- [ ] AC2：保存档案走"整体替换"语义且不丢数据：提交时请求体包含全部档案字段（身高、年龄、性别、健身目标、训练经验、目标体重、档案体重），保存后原先已存在的其它档案字段仍在（请求体断言 + 替身响应回读断言）。
