# 31 — 体重趋势统计与解读区

**What to build:** 身体数据页给了折线图和四个整段窗口的聚合值，但没有一句"最近在往哪走"。用户切换 30 天与 90 天时"总变化"会变，页面上没有任何地方解释口径变了；最低/最高只是两个数字，不知道哪天最低；训练与体重完全不相关，用户看不到练得多的那几周体重怎么走。

这张票在统计卡与趋势图之间加一块"趋势解读"：最近 7 天与最近 30 天各自的变化量与方向、两个窗口内带日期的阶段性最低与最高、最近四周"训练天数 × 体重变化"的并列事实。口径必须说清楚——窗口锚点取最新一条记录而不是今天（几天没称重的用户仍能看到自己的最近 7 天），数据明显陈旧时提示补记，记录不足两条时只说"数据不足"不下结论。

统计与文案全部由一个无副作用纯函数从"体重记录 + 打卡日期集合 + 今天"派生，不新增统计接口、不改记录语义（同一天重复提交仍覆盖、删除后立即重算）。训练与体重只做描述性并列，不做因果声称；文案走正式中文（体重趋势属报告类，不穿插西海岸俚语）。目标体重与目标偏离判断不在这张票里，见 32。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] AC1：解读区显示最近 7 天与最近 30 天各自的变化量（1 位小数、带方向）与方向词（下降/上升/持平/数据不足）；窗口以最新一条记录为锚点：今天无记录但 3 天前有记录时，7 天窗口仍给出结论（纯函数表驱动单测全绿）。
- [ ] AC2：两个窗口各自显示最低与最高体重及其日期；极值并列时取日期更近的一条；窗口内无记录时该窗口极值为空（单测覆盖并列与空窗口两例）。
- [ ] AC3：降级形态可见且互不混淆：窗口内记录少于 2 条显示"数据不足"不显示数值；仅 1 条记录时显示"再记一次就能看出方向"；无任何记录时不渲染解读区（三条渲染断言）。
- [ ] AC4：锚点早于今天 7 天以上时，解读区顶部出现补记提示且结论标注"基于最近一次记录"；窗口内所有体重相同时显示"持平"与 0 变化，不出现百分比抖动或除零错误（两条断言）。
- [ ] AC5：最近四周的周对照显示每周体重变化与训练天数并列，文案只写"同期"事实不下因果结论；打卡数据取不到时周对照整体隐藏、其余解读照常渲染（单测 + 渲染各一条断言）。
