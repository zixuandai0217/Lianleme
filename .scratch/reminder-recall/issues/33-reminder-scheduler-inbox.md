# 33 — 提醒调度宿主 + 投递记录 + 收件箱

**What to build:** 应用启动后自带一个常驻的周期调度宿主，按时钟节拍做一次「tick」；每次 tick 只做规则判定与投递记录写入这两件轻量事，不在 tick 内发起任何外部网络调用或重活。投递记录带唯一约束，同时充当站内收件箱：用户能在应用里看到通知列表与未读数，并把它标为已读。这个票搭的是提醒体系的地基，具体规则与外部推送通道由后续票补齐。

**Blocked by:** 03 结构化日志与请求关联 ID；06 迁移基线对齐与一致性测试

**Status:** ready-for-agent

- [ ] AC1 应用启动后调度宿主处于运行态并按固定间隔 tick；提供可手动触发的 tick 入口（内部/运维用途）以便测试与排障；单次 tick 抛错被捕获并记录，后续 tick 继续正常执行（连续两次 tick 均返回成功摘要）。
- [ ] AC2 一次 tick 写入的站内通知可通过收件箱接口读到：列表返回 200 且含该条通知，未读数为 1。
- [ ] AC3 同一天连续 tick 两次不产生第二条投递记录（唯一键幂等生效），收件箱仍只有 1 条通知、未读数仍为 1。
- [ ] AC4 tick 内不发生外部网络调用（以外部调用替身断言调用次数为 0），且 tick 在秒级预算内完成。
- [ ] AC5 收件箱接口行为可验证：单条已读后未读数减 1、全部已读后未读数为 0；未被授权时读他人通知返回 403、未登录返回 401；管理员不得读取任何用户的通知正文。
- [ ] AC6 应用关闭时调度宿主被优雅取消（关闭后不再产生新投递记录），且重启后再次 tick 不出现双跑导致的重复投递。
