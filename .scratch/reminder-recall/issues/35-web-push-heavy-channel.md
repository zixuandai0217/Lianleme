# 35 — Web Push 重通道

**What to build:** 在站内收件箱之外增加一条需要网络调用的重通道：用户授权后登记浏览器推送订阅，关闭页面也能收到系统级通知。这条通道遵守已有的调度边界——tick 只写投递记录并投递一条持久作业，真正的发送、超时与重试由统一执行器完成；订阅失效（推送服务返回失效响应）时标记失效并不再无意义地重试。服务端未配置推送密钥时该通道整体不可用，且不影响站内通道。

**Blocked by:** 11 DB 驱动执行器；33 提醒调度宿主 + 投递记录 + 收件箱

**Status:** ready-for-agent

- [ ] AC1 推送订阅登记接口返回 200 并持久化订阅，随后查询通道状态显示为「已订阅」；注销后显示「未订阅」；未登录返回 401。
- [ ] AC2 服务端未配置推送密钥时，通道状态查询返回「不可用」，订阅登记被拒绝（4xx 且带稳定错误码），同时站内通知不受影响（照常产生、照常可读）。
- [ ] AC3 通道打开时一次 tick 只写投递记录并投递一条待执行作业；tick 期间外部发送调用次数为 0（用替身断言），发送发生在执行器一侧。
- [ ] AC4 执行器执行成功后投递记录状态为「已发送」；推送服务返回失效响应时该记录标为「失败」、对应订阅标记失效，后续 tick 不再为该订阅投递（可由投递记录数与状态断言）。
- [ ] AC5 同一「用户 + 规则 + 本地日期 + 通道」重复 tick 不产生第二条投递记录，也不产生第二个待执行作业（幂等同时覆盖记录与作业两侧）。
