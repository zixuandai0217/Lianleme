# 01 — 质量门入口（前后端质量命令 + 修跨平台用例）

**What to build:** 让「这个项目现在达标没有」变成一条命令的结论。贡献者在提交前跑一次，就能依次看到前端类型检查、前端 lint、前端单元测试、后端静态检查、后端单元测试的执行结果，每步都有明确的通过/失败与耗时，整体以一个退出码收尾。同一条命令提供快速档（静态检查 + 单元测试，供提交前用）与完整档（再加一条主链路 smoke 与构建自检，供合并前用），两档共用同一份步骤定义。

这条命令要能成为唯一事实来源，前提是「全绿」真的可达成。当前后端全量测试在 Windows 上有一条用例因路径分隔符写死而失败，代码本身没有问题；这张票同时把这处断言改成平台无关，让门在开发机上和 CI 上给出同一结论。之后 CI 只需要调用这条命令，不必再拼第二套逻辑。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] AC1：执行质量门入口命令后，摘要里依次列出五个必需步骤（前端类型检查、前端 lint、前端单元测试、后端静态检查、后端单元测试）的步骤名、退出码、耗时，以及跳过条目数。
- [ ] AC2：全部通过时命令退出码为 0；任一步骤失败时退出码非零，且摘要首行指出失败的步骤名与可定位线索（文件位置或失败断言），不需要翻完整日志才能判断是哪一步。
- [ ] AC3：在 Windows 与 Linux 上分别跑后端全量测试均全绿——原先因路径分隔符写死而失败的唇形同步用例断言改为平台无关，不再出现「同一份代码在某个平台必然失败」的用例。
- [ ] AC4：没有任何用例被静默跳过：因缺少外部二进制而跳过的用例，摘要里列出用例名与原因；未登记的跳过被视为失败。
- [ ] AC5：前端单元测试以单次运行模式执行（执行完即退出，不会停在监听态）；快速档与完整档都能各自跑通，完整档额外包含一条从登录到陪练的主链路 smoke 步骤。
