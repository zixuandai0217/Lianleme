# 38 — CSV 导出 + 导出审计

**What to build:** 运营把当前筛选出来的那批用户一键导成 CSV，拿去表格工具里做二次分析。导出严格沿用列表的筛选与排序，文件用 UTF-8 BOM 编码保证 Excel 打开中文不乱码，列序固定；行数超上限时明确拒绝并要求收窄条件，绝不静默截断。每次导出都留下一条审计记录（谁、什么条件、多少行、什么时候），因为数据流出必须可追溯。

**Blocked by:** 36 用户列表搜索 / 筛选 / flags

**Status:** ready-for-agent

- [ ] AC1 导出返回 200，响应头声明为附件下载、文件名含导出日期；文件字节以 UTF-8 BOM 开头，用 Excel 或解析器打开中文不乱码。
- [ ] AC2 表头为约定的中文列序（用户 ID、昵称、邮箱、openid、注册时间、是否管理员、是否有计划、计划难度系数、累计打卡数、近 30 天打卡数、最近打卡日期、最近活跃时间、是否已做体型分析、Key 状态、需关注标记）；时间列为 ISO 8601、布尔为「是 / 否」、空值留空。
- [ ] AC3 导出的行数与同一筛选条件下列表返回的总数一致；改变筛选条件后导出的行数与内容随之变化（用两次不同筛选各导一次断言），排序与列表一致。
- [ ] AC4 筛选结果为 0 行时返回**仅表头的文件**（不报错、不空白响应）（Lead 裁决，唯一答案）；超过行数上限时返回 4xx 且提示收窄筛选，文件内容不得被静默截断。
- [ ] AC5 每次导出尝试都写一条审计记录——**包括被拒绝的那次**（操作者、筛选条件摘要、行数、时间、结果与被拒原因）（Lead 裁决，唯一答案），可通过只读接口查到；成功的导出不含拒绝原因字段。
- [ ] AC6 导出内容中 openid 与邮箱为掩码形态、不含密码哈希与加密 Key；非管理员发起导出返回 403、未登录返回 401。
