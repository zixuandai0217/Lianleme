# 36 — 用户列表搜索 / 筛选 / flags

**What to build:** 运营要能在几千个用户里直接定位人，而不是一页页翻。用户列表接口支持关键字搜索（昵称、邮箱、openid、用户 ID）、多条件组合筛选（是否有计划、注册时间区间、打卡数区间、最近活跃天数、是否管理员、是否配置 Key）、排序与分页，并为每个人返回派生字段：是否有计划、累计与近 30 天打卡数、最近打卡日期、最近活跃时间、距离今天几天、以及需关注标记。派生字段由服务端一次聚合算出，不再对每个用户逐个查询。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] AC1 关键字搜索对昵称、邮箱、openid、用户 ID 四类输入都能命中相应用户；无匹配时返回 200、空列表且总数为 0（不是 404 或 500）；输入含通配符或引号等特殊字符时不产生全表误命中或 500。
- [ ] AC2 多条件组合筛选返回满足全部条件的交集，且总数与同条件下去掉分页后的实际行数一致；单独条件与组合条件各有用例覆盖。
- [ ] AC3 排序（注册时间升/降、最近活跃升/降）返回顺序符合预期；页码越界返回 200、空列表与正确总数；每页条数超过上限时被拒绝或裁剪为上限（行为在实现中锁定并由测试断言）。
- [ ] AC4 列表每项都含派生字段：是否有计划、累计打卡数、近 30 天打卡数、最近打卡日期、最近活跃时间、距今天数、需关注标记；单次列表请求的数据库查询次数不随当页用户数线性增长（以查询计数断言，例如当页 20 人与 1 人查询次数相同）。
- [ ] AC5 需关注标记可筛选且规则正确：构造数据下「注册超 7 天无计划」「有计划但 7 天无打卡」「14 天无活跃」「注册超 3 天未做体型分析」「未配置 Key」各自只在符合条件的人身上出现，按标记过滤只返回带该标记的用户。
- [ ] AC6 新增/改造后的列表接口自身受保护：非管理员返回 403、未登录返回 401；响应体不含密码哈希或加密 Key 字段名。
