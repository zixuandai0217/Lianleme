# 37 — 用户详情聚合 + 脱敏

**What to build:** 运营点进一个用户，一屏能看到该账号的全貌：基础档案与账号状态、体型分析摘要、当前计划与最近一次计划调整、打卡时间线与连续性、体重序列与记录频率、关键行为轨迹、以及 AI 使用情况。数据按分区组织、单分区缺失不影响其他分区；所有身份字段在接口层就做掩码，密码哈希与加密 Key 永不出现在任何响应里。有了这条链路，运营才可能回答「我的计划为什么被改了」这类投诉。

**Blocked by:** 36 用户列表搜索 / 筛选 / flags

**Status:** ready-for-agent

- [ ] AC1 详情接口返回 200 且含各分区（档案、分析、计划、打卡、体重、轨迹、用量）；对缺计划、缺体型分析、缺体重记录的用户仍返回 200，对应分区为空值而不是报错或 404。
- [ ] AC2 支持按分区请求：只请求部分分区时，响应只返回所请求的分区（其余不返回或为空），且响应体积明显小于全量请求。
- [ ] AC3 脱敏可验证：所有响应中 openid 为掩码形态、邮箱本地部分被掩码、不存在密码哈希与加密 Key；以「完整 openid 原文出现在响应中」为失败断言（响应全文比对）。
- [ ] AC4 行为轨迹按时间倒序返回固定类型事件（注册、首次/最近体型分析、首次生成计划、最近计划调整、首次/最近打卡、首次/最近体重记录、最近对话），支持分页；没有发生过的阶段不伪造事件。
- [ ] AC5 打卡与体重分区的数值与用户自己的统计接口一致（同一用户在详情页看到的连续天数、近 90 天序列条数与自身统计接口返回一致），近 90 天窗口外数据不计入。
- [ ] AC6 非管理员访问他人详情返回 403、未登录返回 401、不存在的用户返回 404；管理员越权读取不产生任何敏感字段泄漏。
