# 22 — 训练会话实体 + 推进 / 恢复接口

**What to build:** 用户点「开始训练」后，服务端为当天建立一条训练会话，之后每完成一组、跳过动作都记在这条会话上；退出、刷新、换设备再回来，进度能接着走。会话以「动作序号 + 组序号」定位，进度指针与完成率都由服务端算好返回，前端不再自己数。这样训练过程第一次有了可恢复的事实来源，也为后面的会话页和打卡反馈提供数据。

**Blocked by:** 06 迁移基线对齐与一致性测试；07 今日接口区分「无计划 / 休息日」

**Status:** ready-for-agent

- [ ] AC1 首次「开始训练」返回 200，会话状态为进行中，响应含会话标识、第一个动作与计划总组数；同一天再次调用返回同一个会话标识，数据库里该用户当天只有一条会话。
- [ ] AC2 「完成一组」返回 200 且已完成组数加一、当前组指针前进；对同一个「动作序号 + 组序号」重复提交，已完成组数不变、响应成功（幂等），不允许进度回退。
- [ ] AC3 「跳过动作」需带跳过原因，返回成功；该动作标记为已跳过、留在明细里，但不计入完成组数，完成率仍按「已完成组数 / 计划总组数」计算。
- [ ] AC4 重新读取会话（模拟退出后再次进入，服务端进程内存清空只留数据库）时，返回的当前动作、已完成组数、可打卡状态与退出前一致；跨零点继续训练仍归属会话开始当天。
- [ ] AC5 越权访问他人会话返回 403、未登录返回 401；在休息日或无计划状态下「开始训练」返回明确的 4xx（带稳定错误码），且不产生空会话记录。
