# 03 — 结构化日志与请求关联 ID

**What to build:** 用户报错时，一句话就能把这次请求的全部日志捞出来。每个请求进来时生成或沿用请求标识，写进响应头、写进本次请求内产生的每条日志，并一路带到它触发的后台任务；用户报出这个编号，值班的人就能把「请求 → 任务 → 结果」串成一条线。

日志从「零散的中文句子」改成单行结构化事件：字段名固定、可被日志系统索引，正常流转记信息级，可预期的业务失败记告警级且不带堆栈，未预期异常记错误级且必带堆栈。对外仍然只返回统一错误形状与安全文案，内部信息不越过边界。任何日志里都不出现 API Key、密码、令牌、图片内容与对话原文。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] AC1：任意请求（含 4xx 与 5xx）的响应头都带请求标识；客户端传入格式合法的标识时被沿用，传入非法或缺失时被替换为新标识（不得原样回显非法值）。
- [ ] AC2：每个请求完成时产生一条单行结构化事件，含方法、路由模板、状态码、耗时、请求标识与用户（未认证时为空），一行一条、不含换行。
- [ ] AC3：未预期异常返回统一错误形状且响应体不含堆栈或异常类名，同时存在一条带完整堆栈的错误级事件；4xx 业务错误产生告警级事件且不带堆栈。
- [ ] AC4：后台任务相关事件带任务标识、用户、尝试次数与错误码，并继承触发它的请求标识；任务失败必有错误级事件与堆栈（可预期的业务失败除外）。
- [ ] AC5：SSE 请求在流开始、正常结束、客户端中断、上游失败四种情况下都有结束事件，其中中断与失败为告警级并带错误类别。
- [ ] AC6：非开发环境下日志为单行结构化输出；开发环境允许人类可读格式，但两种格式的字段集合一致（同一事件不因环境丢失字段）。
