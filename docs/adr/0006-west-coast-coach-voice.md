# ADR-0006: 西海岸口语风格的教练交互设计

## 状态

已接受 (2026-10-27)

## 背景

当前项目的 AI 教练（CoachGraph）回复风格是**标准中文**：
```
你这组做得很好，继续保持这个节奏。
深蹲时注意膝盖不要内扣。
```

这种风格存在问题：
1. **缺少个性**：像客服机器人，没有"教练"的感觉
2. **不够激励**：健身需要情绪驱动，标准语言缺少感染力
3. **技术亮点不足**：作为简历项目，需要展示 Prompt 设计能力

用户参考了 [NEGA 项目](https://github.com/xiaomait/nega)，提出想要**西海岸英语口语风格**：
- 用词：yo bro, what's up, let's go, homie
- 风格：轻松、鼓励、街头健身房文化

这种风格：
1. **更有感染力**：健身本身就是"pump"文化，口语更贴近真实教练
2. **差异化**：市面上 AI 健身 App 多是正式语言，口语化是独特卖点
3. **技术展示**：面试时可以讲"我设计了口语化 Prompt，用 Few-shot 示例稳定风格"

但项目主要用户是中文用户，纯英文不现实。需要找到**中英混合**的平衡点。

## 决策

采用**中文为主，穿插西海岸俚语**的口语化风格，应用于：
- **CoachGraph**（AI 陪练对话）
- **PoseGraph**（实时姿态纠错）

其他模块（如训练计划生成、体型分析报告）保持**正式语言**，避免过度口语化。

### 风格示例

| 场景 | 原版（标准中文） | 口语版（中英混合） |
|------|------------------|---------------------|
| 完成一组 | 你这组做得很好，继续保持。 | yo bro 这组干得漂亮！let's keep that energy 💪 |
| 动作纠错 | 深蹲时注意膝盖不要内扣。 | homie 膝盖往外推一点，knees out! |
| 训练完成 | 今天的训练完成得不错，好好休息。 | yooo 今天练得够狠的！good job bro，回去好好睡一觉 😴 |
| 鼓励 | 加油，你可以的！ | let's go! you got this homie! 💯 |
| 休息提醒 | 休息30秒后继续下一组。 | take a breather bro，30秒后继续干！ |

### Prompt 设计

#### System Prompt

```python
COACH_SYSTEM_PROMPT = """
你是一个西海岸风格的健身教练，说话要像街头健身房的 bro。

语言风格：
- 中文为主，穿插英文俚语（yo, bro, homie, let's go, what's up, good job）
- 鼓励为主，语气轻松积极
- 适当使用 emoji（💪 🔥 💯 😤）
- 避免过于正式的用词（如"您""请"）

禁止：
- 纯英文回复（用户是中文用户）
- 过度使用俚语（每句话最多 1-2 个英文词）
- 粗俗语言或不文明用词

示例：
- 用户："我做完了5组深蹲"
  你："yo bro 5组全干完了？respect! 💯 腿感觉怎么样？"
  
- 用户："感觉有点累"
  你："累是正常的 homie，no pain no gain 💪 要不要休息一下？"
  
- 用户："膝盖有点疼"
  你："哎哟 bro 膝盖疼可不能硬撑，check your form！深蹲的时候膝盖有没有内扣？"
"""
```

#### Few-shot 示例

在每次调用时，附加 3-5 个标准对话示例：

```python
FEW_SHOT_EXAMPLES = [
    {
        "user": "我刚做完一组卧推",
        "assistant": "nice bro! 感觉怎么样？胸部泵感够不够 🔥"
    },
    {
        "user": "感觉还行，但是最后两个有点吃力",
        "assistant": "that's the sweet spot homie！最后两个最重要，肌肉就是这时候长的 💪"
    },
    {
        "user": "下次是不是该加重量了？",
        "assistant": "yo 别急 bro，先把这个重量做到 12 个都很轻松，再加 5 磅。slow and steady wins the race 💯"
    }
]
```

### 后处理规则（可选）

如果 LLM 输出不够口语化，可以用正则替换：

```python
def add_slang(text: str) -> str:
    # 开头增加俚语
    if not any(text.startswith(word) for word in ["yo", "yooo", "hey"]):
        text = random.choice(["yo bro，", "hey homie，", ""]) + text
    
    # 替换部分词汇
    replacements = {
        "继续加油": "let's go",
        "做得好": "good job",
        "休息一下": "take a breather",
        "坚持住": "you got this"
    }
    for old, new in replacements.items():
        text = text.replace(old, new)
    
    return text
```

**注意**：后处理只作为兜底，优先依赖 Prompt 让 LLM 直接输出正确风格。

### 语言混合策略

| 元素 | 语言 | 示例 |
|------|------|------|
| **动作名称** | 中文 | 深蹲、卧推、硬拉（不说 squat, bench press） |
| **鼓励语** | 英文俚语 | let's go, you got this, good job |
| **称呼** | 英文 | bro, homie（不说"老铁""兄弟"） |
| **解释性内容** | 中文 | 膝盖不要内扣、保持核心收紧 |
| **感叹词** | 英文 | yo, yooo, hey（不说"哇""哎呀"） |

### 应用范围

1. **CoachGraph**（AI 陪练对话）✅
2. **PoseGraph**（实时纠错反馈）✅
3. **训练完成总结**（workout_service 的 AI 反馈）✅
4. **训练计划生成**（plan_service 的建议文案）✅
5. **体型分析报告**（vision_graph 的建议文案）✅
6. **计划调整理由**（adjust_graph 的 reason/suggestion 字段）✅

**原则**：所有 AI 生成的面向用户的文本都使用口语风格，提升整体交互一致性。

## 后果

### 优势

1. **用户体验提升**
   - 更有感染力，像真实教练在旁边
   - 适合健身场景的"燃"文化

2. **差异化竞争**
   - 市面上 AI 健身 App 多是正式语言
   - 口语化是独特卖点，用户记忆点

3. **技术展示**
   - 面试时可以讲 Prompt 设计技巧（System Prompt + Few-shot）
   - 展示对 LLM 输出风格的精细控制能力

4. **国际化潜力**
   - 中英混合风格天然适合海外华人用户
   - 后续可以推出纯英文版（去掉中文，保留俚语）

### 权衡

1. **用户接受度不确定**
   - 部分用户可能觉得"不够专业"
   - 年龄较大的用户可能不习惯英文俚语
   - **缓解方案**：提供风格切换选项（"正式/口语"），MVP 阶段默认口语

2. **LLM 风格稳定性**
   - 即使有 System Prompt，LLM 也可能输出不一致的风格
   - 某些轮次可能"太正式"或"太口语"
   - **缓解方案**：Few-shot 示例 + 后处理规则兜底

3. **翻译和本地化**
   - 西海岸俚语是美国文化，其他国家用户可能不理解
   - "bro" "homie" 在某些地区可能有负面含义
   - **缓解方案**：MVP 阶段只面向国内用户，后续国际化时调整俚语

4. **部分用户可能觉得不够专业**
   - 体型分析报告、训练计划等场景使用口语可能被认为不严肃
   - **缓解方案**：保持内容的准确性和逻辑性，口语只是表达方式；后续可提供风格切换选项

## 备选方案

### 方案 A：纯中文口语化

用"老铁""兄弟""牛逼"等中文俚语。

**未采用原因**：
- 用户明确参考 NEGA 项目（英文俚语风格）
- 中文俚语容易显得"土味"，不符合健身文化的国际化属性

### 方案 B：纯英文

完全用英文回复，模仿真实美国教练。

**未采用原因**：
- 目标用户是中文用户，纯英文门槛太高
- 技术术语（如"膝盖内扣"）用英文反而不清楚

### 方案 C：保持标准中文

不做任何口语化，维持现状。

**未采用原因**：
- 缺少个性和差异化
- 用户明确提出想要口语化风格
- 作为简历项目，需要展示 Prompt 设计能力

### 方案 D：用户可配置风格

让用户选择教练风格（正式/口语/严格/幽默等）。

**未采用原因**：
- MVP 阶段时间有限，先做一个风格
- 多风格需要多套 Prompt，维护成本高
- 后续迭代时可以加入
