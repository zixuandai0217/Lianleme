# ADR-0009：五维合并与方向决策规则

## 状态

已采纳（工单 24，配套 `adaptive-plan-adjustment` spec）。

## 背景

工单 24 把调整评估从「只看完成率」升级为五个维度并行体检，再由 Merge Node 汇总成
一个整体判断。ADR-0001 定义了「5 路并行分析器」的拓扑，ADR-0003 定义了混合分析器的
阈值，ADR-0004 定义了人机协同的中断条件，但都没有规定**多份分数如何合成一个方向**。
没有这条规则，五个分析器各自给出分数与建议，落地时仍会退化成「完成率说了算」，或者
每次实现调整都重新拍一次权重。规则必须在代码之外有一份可引用的决策记录。

## 决策

### 1. 单维输出统一形状

每个分析器输出 `{name, score(0-10), reason, suggestion, source(rule | llm), degraded,
data_completeness(full | partial | default)}`。`default` 明确表示「这一维没有可用数据，
用了缺省值」，与「真实评估很低」区分开。

### 2. 合并用等权平均，剔除缺省维度

参与合并的维度等权平均（规则型与模型型同权，不按实现方式加权）；`default` 维度不参与
均分并列入 `excluded_dimensions`，前端据此标注「未评估」。全维缺省时整体分为 0，方向
保守取 `keep`，不编造分数。

理由：五维在设计上互相补位（完成率看执行、疲劳看恢复、伤病看风险、睡眠看恢复质量、
体成分看长期趋势），没有证据支持任何一维长期更重要；固定权重会在数据缺失时把缺失
当成低分。等权 + 剔缺省在数据逐步补齐的过程中保持可比。

### 3. 风险信号旁路，不稀释均分

风险信号只用于提示与后续中断，不并入平均分（否则高风险会被高分维度平均掉）。工单 24
只产出当前数据足以判定的信号：伤病风险评分 ≤3（工单 25 接入后生效）、完成率 <50%、
疲劳健康评分 ≤5。「连续多次大幅调整」与「减脂期体重上升」需要调整历史与体重趋势，
按工单 27 接入，届时以同样的 `{code, severity, evidence}` 形状追加。

### 4. 方向阈值与保守冲突规则

整体分 ≥7.5 → `increase`（声明幅度 +12%）；5.0–7.5 → `keep`；<5.0 → `decrease`
（−18%）。当完成率极值（≥80% 指向加量、<50% 指向减量）与合并分指向的方向冲突时，
取更保守的一方（`decrease` > `keep` > `increase`）。

理由：幅度沿用现状量级（ADR-0003 的 10–20% 区间中点）；保守规则避免「换了一套评分
实现」的那一周方向反复横跳——用户看到的计划变动必须可解释。

### 5. 工单 24 的落地方式

工单 24 不做模型调用：三路规则分析器 + 两路「未评估」占位即可产出五维小结与方向，
整趟评估在模型替身计数为 0 的前提下完成。落地只确定性地缩放 `difficulty_factor`
（整数动作组数表达不了 10–18%），逐动作重排留给 27/28。

## 后果

- 五维形状与合并规则成为工单 25/26/27 的共同契约；新维度只需注册进分析器表，不改
  Merge Node 的加权逻辑。
- 缺省维度不参与均分，意味着数据越全分数越有代表性；运营与用户看到「未评估」时能
  理解这是缺数据而不是低分。
- 风险信号与方向解耦：高风险不一定立刻改变方向（可能已经是最保守的 `decrease`），
  但一定出现在信号列表里。
- 历史幅度与目标偏离两类信号留到 27；在它们接入前，风险列表可能为空，这是数据不足
  而非实现遗漏。
