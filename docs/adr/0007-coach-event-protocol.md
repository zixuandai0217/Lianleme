# ADR-0007：陪练流式输出改用结构化事件协议

- 状态：已接受（2026-11-01）
- 背景文档：[陪练协议帧工单](../../.scratch/coach-stream-protocol/issues/17-coach-protocol-frames-and-cleanup.md)、[陪练协议规格](../../.scratch/coach-stream-protocol/issue.md)

## 背景

陪练的流式接口原先把模型的每个文本增量直接拼进单行 `data:`，用 `data: [DONE]` 收尾。这带来三类问题：

1. **协议不可表达**：正文、错误、教练状态、快捷动作全挤在同一个文本通道里，前端只能靠字符串猜测含义；模型输出里一旦出现换行（JSON 外壳、代码块），按行切分就会把一帧切成两半。
2. **失败与正文混排**：上游失败时，一句中文提示被当作普通 token 发进气泡，用户看到的是「教练在正文里说话」，而前端无法区分「教练说了这句」与「系统错误」。
3. **泄漏进历史**：入库保存的就是未经清洗的原始流，于是 JSON 外壳与代码围栏会随着历史回放在用户面前再演一遍。

## 决策

陪练流式接口改为**结构化事件协议 v1**：

- 每帧是一行 JSON，帧之间空行分隔；类型判别放在 JSON 的 `type` 字段上，不使用 SSE 的 `event:` 字段（避免两种判别方式并存）。
- 事件类型固定为六类：`turn_started`（一轮的开始，含 `turn_id`）、`message_chunk`（正文增量）、`state`（教练状态）、`actions`（服务端下发的快捷动作）、`error`（稳定错误码 + 可读文案）、`done`（唯一终结帧，含 `finish_reason`）。
- 正文只来自 `message_chunk`；`error` 不进入气泡正文，前端以独立提示单元展示；`done` 之后不再有帧，迟到的旧轮次帧按 `turn_id` 丢弃。
- 模型原始输出在离开服务端前统一清洗（JSON 外壳、代码围栏、结构残留），**只有清洗后的正文进入帧与数据库**，因此实时与历史回放内容一致。
- 不再使用 `data: [DONE]`。

## 影响

- 前端多出一个与 React 无关的协议层（帧解码器 + 轮次归约器），页面只消费归约结果，不再自行切分 `data:`。
- 协议是跨端契约：`state` / `actions` 两类帧的形状在本决策定稿，具体下发规则由后续能力补齐；在补齐前前端必须能忽略未知/缺失字段。
- v1 不承诺跨版本兼容（前后端同仓同部署），`protocol` 字段保留用于灰度与日志定位。

## 被否决的方案

- **继续用纯文本 + 前端启发式解析**：无法解决「错误与正文混排」，且每次清洗规则变化都要在前后端各改一次。
- **在 SSE 的 `event:` 字段上做类型**：客户端会出现两条并行判别路径，测试与转发都更容易分叉。
